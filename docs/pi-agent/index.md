# 前言

## 为什么要写这个专栏？

这两年做 AI 编程的人，多半都遇到过同一个问题：Claude Code、Codex、Cursor 一个接一个冒出来，功能都越来越强，但每换一个，配置、习惯、Workflow 就得重来一遍。

一开始想看清的只有一件事——**能不能有一个足够小的 Agent 内核，可以理解它、改它，并且把积累下来的 Skill、工具、工作流继续带走**？

Pi 让这条路看起来能走通。它官方定位就是「一个极简的终端 Coding Harness」，模型、工具、上下文、交互都可以往上搭；默认能力克制，缺的东西自己动手补。这恰好是值得在上面折腾的原因。

## 专栏涉及内容

这个专栏分四篇，一篇讲 Pi 本体，一篇讲本机装了哪些插件，一篇讲 Codemode 这个内建的上下文机制，一篇讲 Hindsight 记忆系统。

- **[Pi 本体：极简 Agent Harness](./core)**  从「Pi 是什么、不是什么」讲起，把架构、默认工具集、Skill 加载策略、可迁移性说清楚。同时会引用 Databricks、PointFive、Composio 三组公开数据，看 Pi 在 Token 效率、任务成本、执行速度上到底能省多少、又会多花在哪。
- **[优秀插件：本地实测的 Pi 扩展](./plugins)**  列出当前正在用的扩展和 Skills，逐个说明它们为什么值得装、解决了什么具体痛点。这里不吹 Pi 生态有多大，只讲本机真正跑起来的组合。
- **[Codemode：把工具调用写成脚本](./codemode)**  讲 Pi 内建的 `codemode` 怎么让模型写脚本编排工具、只把结论带回上下文，以及它为什么替掉了第三方的 `context-mode`。
- **[Hindsight：为什么选它作为 Agent 记忆体](./hindsight)**  讲 Hindsight 把存储/检索/推理拆开的设计逻辑，Retain / Recall / Reflect 三个动作为什么能降低记忆污染风险，以及它为什么是更合适的记忆方案。

写这个专栏之前，先在 Pi 上折腾了两周，装过十几个扩展，退过几个不合适的，也踩过几次权限和沙箱的坑。专栏里出现的判断都来自这一段实测，而不是从官方文档里直接抄一段过来。

Pi 不是最完整的 Coding Agent，它开箱的状态甚至有些粗糙——没有默认沙箱、没有开箱即用的权限系统。但对想理解 Agent 是怎么跑、并且希望把工作流握在自己手里的人来说，这种「不完整但透明」反而是一种优势。

接下来的几篇文章会尽量用数据说话，也会把反例放上桌——如果一个 Benchmark 不能支持 Pi 的结论，也会写清楚。
